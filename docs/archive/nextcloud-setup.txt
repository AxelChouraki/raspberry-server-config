	Objectif initial

Un seul point d’accès (Nextcloud sur RPi2 avec SSD).
Réplication automatique des données utilisateur entre plusieurs serveurs distants.
Gestion de configuration centralisée via Ansible.
Monitoring et alertes (déjà en place avec Prometheus et Grafana).
Sécurité et résilience en cas de panne d’un des nœuds.

	Choix du système ----------------------------------------------

Je souhaite une application avec un interface utilisateur pour se faciliter la vie et pas des envois de fichier avec scp et une synchronisation avec rsync.
Je souhaite aussi une config au minimum "pro" et limiter le custom au maximum
Nextcloud a l'air d'être le système de cloud le plus connu pour les systèmes de cloud privés. Mais il ne gère pas nativement la réplication. je me tourne donc vers SeaFile, qui a certes moins de fonctionnalités collaboratives mais qui a une réplication native et une meilleure performance. 


	Pourquoi Seafile est adapté à mon besoin ---------------------------

Architecture basée sur des blocs, ce qui réduit la quantité de données transférées lors des synchronisations.
Réplication native et intégrée entre serveurs, avec possibilité de mettre en place un cluster.
Supporte la synchronisation multi-sites avec une meilleure cohérence que Nextcloud en mode distribué.
Plus léger en consommation de ressources que Nextcloud, donc mieux adapté à Raspberry Pi.
Interface web et clients légers, même si moins riche en apps collaboratives.

  --> pour la version pro qui autorise, en autres, plusieurs front serveurs, on est limité à 3 utilisateurs
  --> type de stockage propriétaire
On laisse tomber Seafile

📁 Un système de fichiers (et non un outil de collaboration comme Nextcloud/Seafile)

Mais du coup, n'aurais-je pas juste besoin d'un NAS ? 
🔍 Comparaison GlusterFS vs NAS traditionnel
Critère                       🧱 GlusterFS (cluster distribué)         📦 NAS (centralisé, ex: Synology/OMV)
🔁 Réplication               ✔️ Native, automatique, multi-nœuds       ❌ Pas natif (RAID ≠ réplication distribuée)
🧠 Architecture              Distribuée, décentralisée décentralisée   souvent 1 seule machine
💥 Tolérance aux pannes      ✔️ Oui, si bien configuré (réplica ≥ 2)   ❌ En panne = plus de service
🌍 Déploiement géographique  ✔️ Possible (attention à la latence)      ❌ Difficile à faire sans VPN ou tunneling
⚙️ Customisation             ✔️ Très flexible (Linux, scripting, ACL, etc.)  🔶 Limité aux options prévues par l’OS
📡 Accès réseau              FUSE, NFS, SMB, S3 (via plugins)            NFS/SMB/DLNA/Web — natifs
🔐 Sécurité                  Dépend de ta config (chiffrement, VPN, etc.)  Souvent mieux packagée dès le départ
📈 Scalabilité               ✔️ Ajout facile de nœuds, disques, volumes  ❌ Dépend du matériel du NAS (souvent figé)
🧩 Complexité d’install      🔺 Moyenne à haute (cluster, peer, volumes, bricks)  🔽 Très simple (UI web, install guidée)
🚀 Performances              Bonne si bien configuré (SSD/cache, réseau) Excellente en local si bon matériel RAID
🆓 Coût logiciel Gratuit    (FOSS, 100% Linux)  Gratuit si DIY / payant si Synology/QNAP
📱 Interface utilisateur     CLI ou outils comme Cockpit, Ansible  UI web complète, mobile-friendly
🔄 Sauvegarde externe        À mettre en place manuellement (rsync, borg, etc.)  Plugins/cloud intégrés (S3, GDrive, etc.)


Pour résumer, je pense que GlusterFS est plus adapté à ce que je veux faire: distribué (cluster), réplication, reliable (si un serveur tombe, un autre prend le relai -->  sans point de défaillance unique )

  Installation de Nextcloud pour l'expérience -----------------------------------

L'installation all-in-one clef en main de nextcloud AIO n'est pas faite pour ARM donc je ne prends pas le risque de l'utiliser sur une architecture non supportée.

Étape 0:
  c'est conseillé d'avoir une partition distinct du système
  s'assurer que le user www-data existe

Étape 1 : Mettre à jour ta Raspberry Pi
  sudo apt update
  sudo apt upgrade -y

Étape 2 : Installer le serveur web, PHP, et la base de données
  Nextcloud nécessite un serveur web (Apache ou Nginx), PHP, et une base de données (MariaDB ou MySQL).
    sudo apt install apache2 mariadb-server libapache2-mod-php php php-mysql php-gd php-curl php-xml php-mbstring php-zip php-bcmath php-intl php-imagick php-redis php-gmp php-bz2 php-ldap unzip -y

Étape 3 : Configurer MariaDB
  Sécurise MariaDB et crée une base de données pour Nextcloud.
    sudo mysql_secure_installation
    sudo mariadb
      CREATE DATABASE nextcloud;
      CREATE USER 'nextclouduser'@'localhost' IDENTIFIED BY 'motdepassefort';
      GRANT ALL PRIVILEGES ON nextcloud.* TO 'nextclouduser'@'localhost';
      FLUSH PRIVILEGES;
      EXIT;

Étape 4 : Télécharger et installer Nextcloud
  cd /var/www/
  sudo wget https://download.nextcloud.com/server/releases/latest.zip
  sudo unzip latest.zip
  sudo chown -R www-data:www-data nextcloud
  sudo chmod -R 755 nextcloud

Étape 5 : Configurer Apache
  sudo nano /etc/apache2/sites-available/nextcloud.conf
    <VirtualHost *:80>
        DocumentRoot /var/www/nextcloud/
        ServerName ton_ip_ou_nom_de_domaine

        <Directory /var/www/nextcloud/>
            Options +FollowSymlinks
            AllowOverride All
            Require all granted
        </Directory>

        ErrorLog ${APACHE_LOG_DIR}/nextcloud_error.log
        CustomLog ${APACHE_LOG_DIR}/nextcloud_access.log combined
    </VirtualHost>
  Active le site et les modules Apache nécessaires :
    sudo a2ensite nextcloud.conf
    sudo a2enmod rewrite headers env dir mime setenvif ssl
    sudo systemctl restart apache2

Étape 6 : Vérifier le parefeu
  vérifier que le firewall autorise le flux sur le port 80
    sudo nano /etc/nftables.conf
      # Autoriser HTTP (port 80)
      tcp dport 80 accept
    sudo nft flush ruleset
    sudo nft -f /etc/nftables.conf
    sudo nft list ruleset

Étape 7: Désactive le site par défaut pour éviter les conflits:
  sudo a2dissite 000-default.conf
  sudo systemctl reload apache2


Étape 8 : Finaliser l’installation via le navigateur
  http://adresse_ip_de_ta_raspberry_pi/nextcloud
  Tu devrais voir l’interface d’installation Nextcloud. Crée un compte admin, indique la base de données (user, mot de passe, nom de la base), puis lance l’installation. 

Étape 9: Sécuriser l'installation:
  ajouter les applications suivantes sur nextcloud admin:
    Two-Factor TOTP Provider
    Two-Factor Authentication via Nextcloud notification
    Suspicious Login
    Auditing / Logging
  Dans Administration --> paramètres de base --> forcer la compatibilité windows

Bonus : Sécuriser avec HTTPS
  Générer un certificat dans cloudflare et les ajouter à /etc/ssl/cloudflare_origin.pem et /etc/ssl/private/cloudflare_origin.key
  donne les droits aux clefs
    sudo chown root:www-data /etc/ssl/cloudflare_origin.pem /etc/ssl/private/cloudflare_origin.key
    sudo chmod 640 /etc/ssl/cloudflare_origin.pem /etc/ssl/private/cloudflare_origin.key

  puis ajouter à la config apache: sudo nano /etc/apache2/sites-available/nextcloud.conf
    <VirtualHost *:80>
        ServerName genkis.org
        Redirect permanent / https://genkis.org/
    </VirtualHost>

    <VirtualHost *:443>
        ServerName genkis.org
        DocumentRoot /var/www/nextcloud

        SSLEngine On
        SSLCertificateFile /etc/ssl/cloudflare_origin.pem
        SSLCertificateKeyFile /etc/ssl/private/cloudflare_origin.key

        <Directory /var/www/nextcloud/>
            Options +FollowSymlinks
            AllowOverride All

            <IfModule mod_dav.c>
                Dav off
            </IfModule>

            SetEnv HOME /var/www/nextcloud
            SetEnv HTTP_HOME /var/www/nextcloud
        </Directory>

        ErrorLog ${APACHE_LOG_DIR}/nextcloud_error.log
        CustomLog ${APACHE_LOG_DIR}/nextcloud_access.log combined
    </VirtualHost>
  Active et recharge apache:
    sudo a2ensite nextcloud.conf
    sudo a2enmod ssl rewrite headers env dir mime
    sudo systemctl reload apache2


  Tant que tu tiens à jour Nextcloud, ton OS, Apache, PHP, et que tu utilises un mot de passe fort, c’est relativement sûr.
  Utiliser Cloudflare en reverse proxy avec un WAF et protection DDOS est bien.
  Active la validation à deux facteurs (2FA) sur Nextcloud pour sécuriser les comptes.
  Faire des sauvegardes régulières (de la base + des fichiers).
  Vérifier les problèmes dans Nextcloud --> Administration --> Vue d'ensemble
  Ne pas oublier la redirection de port du routeur
